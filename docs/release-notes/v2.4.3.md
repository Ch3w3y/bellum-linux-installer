GPU crash diagnostics are now requested by default on all Bellum GPU profiles.
The pinned Proton's vkd3d-proton uses `VK_KHR_device_fault`; reports and vendor
binary dumps depend on what the installed GPU driver supports. This preserves
the NVIDIA descriptor-heap workaround. Update an existing Bellum installation
to regenerate `launch_vars.env` with the new setting.

After a GPU crash, collect `launcher.log` from the Bellum install folder and,
if produced, `vkd3d-proton.fault.bin` from the game's working directory. Include
your GPU and driver version when reporting the crash. Fault diagnostics can add
overhead and delay shutdown during crash collection. Remove `fault` from
`VKD3D_CONFIG` in `launch_vars.env` to opt out. Hardware and Easy Anti-Cheat
validation remain manual; successful build checks do not establish gameplay
compatibility.

Scheduled runtime pin checks now fail visibly when verification fails, while
still reporting the problem. Five regression tests cover success, failure,
missing summaries, reporting and the final workflow gate.

Release notes now cover the exact runtime pins and checksums, installer changes,
known launcher build additions, and all intervening upstream Proton/umu release
notes when their pins change. Publication stops if that upstream release history
cannot be retrieved completely. This release keeps the October 15 Proton and
umu 1.4.4 pins unchanged; it does not claim a newer runtime was verified.
